## The Problem L5 Solves

**L4 can answer:**
```
Q: "What is PaymentGW's current latency?"
A: "185ms"
```

**L4 CANNOT answer:**
```
Q: "Assess whether PaymentGW is reliable and recommend improvements"

L4 approach: ❌ Single query → incomplete answer
"PaymentGW's current latency is 185ms" (missing: incidents, SLA, trends, recommendations)
```

**L5 approach:**
```
Q: "Assess whether PaymentGW is reliable and recommend improvements"

L5 investigation plan:
1. Check current status (tool: get_service_metrics)
   → Result: Healthy, 185ms, 0.08% error
   
2. Query incident history (tool: query_incidents)
   → Result: 3 incidents in Q1, including 1 P1
   
3. Read postmortems (KB: postmortem_INC005_paymentgw_mar.md)
   → Result: Circuit breaker stuck, 3 hours downtime
   
4. Check SLA compliance (tool: get_metrics + query_sla_targets)
   → Result: Within SLA but borderline (185ms vs 200ms target)
   
5. Check cost trends (tool: query_costs)
   → Result: March spike to $7,500 (incident-related)
   
6. Read capacity planning (KB: capacity_planning_q2_2026.md)
   → Result: Horizontal scaling recommended
   
7. Synthesize findings:
   ✓ Currently healthy
   ⚠️ Had worst Q1 incident (P1, 3 hours)
   ⚠️ Circuit breaker review overdue (April 15)
   ⚠️ Latency close to SLA limit
   ⚠️ Cost spike in March
   
8. Generate recommendations:
   1. Complete circuit breaker review (overdue)
   2. Implement horizontal scaling
   3. Add automated health check monitoring
   4. Review cost optimization opportunities
```

### 2. Multi-Step Execution

**Sequential execution với dependency:**
```
Step 1: Get service name from user query
  ↓
Step 2: Check current metrics (depends on Step 1)
  ↓
Step 3: Query incidents for that service (depends on Step 1)
  ↓
Step 4: Synthesize (depends on Step 2 + 3)
```

**❓ PRACTICE QUESTION 3:**
Nếu Step 2 mất 3s, Step 3 mất 2s, Step 4 mất 1s.
Total time = 6s (sequential).

Có thể parallel Step 2 và Step 3 không? (cả 2 đều depend on Step 1)
Làm thế nào implement parallel execution?

### 3. Result Synthesis

**Combine results từ nhiều sources:**
```python
synthesis = {
    'current_status': {...},      # From tool
    'incident_history': {...},    # From tool
    'postmortem_insights': {...}, # From KB
    'sla_compliance': {...},      # From tool + KB
    'cost_trends': {...},         # From tool
    'recommendations': [...]      # Generated by LLM
}
```

## Implementation Approach

### Option A: Agent-Driven (Recommended)

**Let Bedrock Agent handle planning:**
```python
# Agent automatically breaks down investigation
result = agent.invoke_agent(
    "Assess PaymentGW reliability and recommend improvements",
    enable_trace=True
)

# Agent will:
# 1. Create investigation plan
# 2. Execute steps sequentially
# 3. Synthesize results
# 4. Generate recommendations
```

**Pros:**
- Less code
- Agent handles complexity
- Built-in retry logic

**Cons:**
- Less control
- Harder to debug
- May not follow optimal plan

---

### Option B: Manual Orchestration

**You control investigation flow:**
```python
class InvestigationOrchestrator:
    def assess_reliability(self, service: str):
        # Step 1: Current status
        metrics = self.tools.get_service_metrics(service)
        
        # Step 2: Incidents
        incidents = self.tools.query_incidents(service=service)
        
        # Step 3: Postmortems
        postmortems = self.kb.retrieve(f"{service} postmortem")
        
        # Step 4: SLA
        sla = self.tools.query_sla_targets(service)
        
        # Step 5: Synthesize
        report = self.synthesize(metrics, incidents, postmortems, sla)
        
        return report
```

**Pros:**
- Full control
- Predictable flow
- Easy to debug

**Cons:**
- More code
- Less flexible
- Need to handle errors manually

## Common Issues

### Issue 1: Incomplete Investigation

**Symptom:** Agent stops after 2-3 steps, doesn't complete full investigation

**Fix:** Improve agent instructions:
```
For investigation tasks, you MUST:
1. Gather data from ALL relevant sources
2. Cross-reference findings
3. Identify patterns and correlations
4. Generate comprehensive recommendations
Do not stop until investigation is complete.
```

---

### Issue 2: Shallow Recommendations

**Symptom:** Recommendations too generic ("improve monitoring", "add resources")

**Fix:** Prompt for specific, actionable recommendations:
```
Recommendations must be:
- Specific (not generic)
- Actionable (clear next steps)
- Prioritized (most important first)
- Justified (explain why)
```

---

### Issue 3: Missing Data Sources

**Symptom:** Investigation only uses tools, ignores KB (or vice versa)

**Fix:** Explicit instruction to use both:
```
For investigations, you MUST combine:
- Live data from tools (current state)
- Historical context from KB (policies, postmortems)
- Synthesis of both for complete picture
```
